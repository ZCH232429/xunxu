# 循序 iOS 测试版 0.1.0

此阶段为 Expo Go 原生外壳 + 共用工作台界面，方便持续迭代，并非已上架的独立 iOS 安装包。

## 已接入

- 今日总览、身体趋势、训练、冰箱与饮食、周期复盘、设置六个板块。
- 既有深色色块 UI；使用用户提供 PingFang 的简体常规与 Semibold 字体子集，总计约 1.03 MiB。动态文字未包含的字形回退到 iOS 系统 PingFang。
- 手机档案保存到原生 AsyncStorage，和测试地址解耦；个人/演示档案分开，写入前沿用原有数据校验。
- 原生拍照/相册、原生商品码扫描、备份导入与系统分享导出。
- 既有写实 3D 人体指导与视频片段。
- 厨房 AI 与食材识别转发到电脑侧现有豆包服务。供应商密钥保留在电脑加密配置，不打包进客户端。

## 启动与修改

运行 `script/preview-phone.cmd`，或在本项目的 Codex Run 操作中启动。
保持电脑开机和该服务运行，在 Expo Go 中打开本账号的新二维码。
桌面工作台源文件更新后运行 `npm run sync:workbench`，随后在 Expo Go 重新加载。
手机专用样式与桥接位于 `workbench-overrides/`；原生实现位于 `components/workbench-native.tsx`。不要直接修改生成的 `public/workbench/app.js`。
Metro 配置变化需要重启服务。界面代码可以在开发服务运行中继续修改。

## 连接厨房 AI

首次打开“我的设置” → “连接厨房 AI / 测试设置”，输入电脑提供的测试配对码。
配对码由电脑生成并保存在 `.expo/native-pairing.json`，手机存入 SecureStore；它不是豆包 API 密钥。
服务路径 `/native-api/` 拒绝未配对请求。隧道地址本身不等于 AI 授权。
此后台是开发服务中间件，只适用于当前 Expo 测试；正式安装包需要另行部署经过认证的后端。

## 真机验收顺序

1. 六个底栏页面切换，检查 PingFang、长内容、刘海和底部手势区域。
2. 录入体重后退出重开，确认记录仍在。
3. 从电脑导出 JSON 后导入手机；不要在未导出备份前覆盖已有手机档案。
4. 相册选择/拍摄清晰韩文营养标签，检查营养基准和实际克重；扫码识别实物包装。
5. 打开写实人体指导，测试旋转、播放、拖动和原视频。
6. 键盘弹出时填写档案、录入食材、提问，检查底部按钮是否被遮挡。

Apple 健康/Apple Watch 自定义模块不能在 Expo Go 中启用。语音先使用 iPhone 键盘听写；App 内持续语音交互、离线资源包、设备间自动同步和 TestFlight 分发尚未实现。
浏览器模拟验收不替代 iPhone 相机、文件分享和 WebGL 性能实测。
