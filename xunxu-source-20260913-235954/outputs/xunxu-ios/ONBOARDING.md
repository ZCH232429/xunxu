# 基础信息与视频起始饮食方案

已实现注册/登录后检查当前用户云端档案。没有 onboardingVersion=1 的有效档案时，展示原生基础信息填写页。旧用户保留原有训练、食物、饮食记录；新档案第一次填写时添加初始体重记录。保存成功才进入工作台。重新编辑前读取最新云端版本；陈旧版本保存被 RPC 拒绝。

输入：可选名称、身高 cm、参考体重 kg、年龄、生理性别公式参数、整体活动水平、每周运动次数、每次平均时长。

计算：BMI = kg/(cm/100)^2；静息能量 Mifflin–St Jeor；TDEE = 静息消耗 × 整体活动系数（1.2/1.4/1.6/1.8 为粗略估计，不再次加运动）。视频目标按审核通过的 2–3/4–5/6–7/8–9 小时表计算。所有系数来自已有 diet_transcript.jsonl 和 diet_300.jpg，详见 lib/nutrition-plan.js。

视频未覆盖的时长没有自动插值：先显示无目标，允许用户明确选择参考档并标注“手动参考”。本次没有创建新数据库表，所有新增字段仍保存在 workspaces.state.profile。

目标按用户确认的参考体重固定，不因单日称重变化自动减餐；7–10 天观察建议显示在确认页，10 天是视频观察提示，本次未新增自动复盘定时器。视频宏量目标不用再次扣 profile.deficit。视频摄入与 TDEE 分开显示，不能把推算缺口当实测。

今日总览/饮食页 targets() 使用同一计算模块。用户从“营养目标”或“我的设置”重新进入原生编辑页。保留独立的训练模板、复盘周期等原有设置。使用视频方案时，旧版固定减 100 kcal 的操作转到重新确认页，避免显示已调节但目标未变化。

验证：
- npm run test:nutrition：BMI、RMR、TDEE、8 组系数、未覆盖区间、手动档、无效输入、目标不随称重自动改变。
- work/test-basics-ui.mjs：React Native Web 渲染，模拟 Supabase 的失败/成功保存、重新加载、重新编辑和档位校验；未操作真实用户数据。
- work/test-video-workbench.mjs：WebView 桥接模拟，今日总览/饮食页目标一致、编辑入口可达、训练偏好保留。
- npm run typecheck；iOS export。

限制：尚需 iPhone Expo Go 实测键盘、滚动、本人账号云端保存和重新登录。浏览器可测试原生基础信息页，完整工作台仍以 Expo Go 为入口。Windows 已安装程序本次未打包更新。
